# PRD 02: Pipeline de Transcodificação FFmpeg & Entrega OTT (HLS/DASH)

**Objetivo:** Processar o vídeo bruto de forma assíncrona gerando múltiplos perfis de resolução e taxa de bits adaptativa (ABR), disponibilizando uma *Master Playlist* HLS servida via CDN e renderizada no Moodle via player customizado.

### Requisitos Funcionais (RF)

* **RF2.1 - Gatilho Assíncrono**: Um evento de upload no bucket de entrada (ObjectCreated Event / Webhook) despacha uma mensagem para uma fila de processamento (ex: SQS / RabbitMQ).
* **RF2.2 - Transcodificação ABR**: Um worker FFmpeg converte o arquivo bruto em múltiplos fluxos de vídeo H.264/AAC segmentados em HLS (tempo de corte: 6s):
* **1080p**: 5000 kbps (1920x1080)
* **720p**: 2800 kbps (1280x720)
* **480p**: 1400 kbps (854x480)
* **360p**: 800 kbps (640x360)


* **RF2.3 - Webhook de Conclusão**: Ao finalizar, o worker grava os segmentos e o `master.m3u8` no bucket de entrega e notifica o Moodle via endpoint REST/External Service atualizando o status para `READY` e salvando a `manifest_url`.
* **RF2.4 - Visualizador do Aluno (`view.php`)**: O aluno acessa a página e consome o fluxo através do **Video.js** configurado com suporte ABR, ajuste de velocidade e controles responsivos.

### Critérios de Aceite

* O player deve se adaptar dinamicamente à largura de banda do usuário sem interrupção abrupta de áudio.
* A URL do manifesto só é disponibilizada para visualização se o status for `READY`.
